# Cuando crees un proyecto nuevo:

Por ejemplo:  
```
proyecto-x
```

podrás conectar el conocimiento así:

```
git submodule add https://github.com/jlbellongmail/ai-knowledge knowledge
```

Entonces la estructura de tu proyecto será:

project-x
│
├── docs
├── src
├── prompts
│
└── knowledge
     (ai-knowledge)


# Esto es lo que evita que tu ecosistema se vuelva caótico cuando crezca.

El problema que queremos evitar es este:

Tienes project-x usando ai-knowledge.

Actualizas ai-knowledge con nuevas skills o cambios.

De repente project-x deja de funcionar o los agentes cambian su comportamiento.

Esto pasa mucho cuando no hay versionado del conocimiento.

1️⃣ Principio clave: el conocimiento también se versiona

No solo el código se versiona.

También deben versionarse:

- skills
- prompts
- prácticas
- arquitectura
- reglas de agentes

Por eso ai-knowledge debe tratarse como una librería.

Igual que:

- una librería npm
- un paquete python
- un framework

2️⃣ Sistema recomendado: Semantic Versioning

Usaremos el estándar:
```
MAJOR.MINOR.PATCH
```

Ejemplo:

```
1.0.0
1.1.0
1.2.0
2.0.0
```

Significado:

```
| Versión | Cambio                    |
| ------- | ------------------------- |
| PATCH   | correcciones              |
| MINOR   | nuevas skills compatibles |
| MAJOR   | cambios que pueden romper |
```

3️⃣ Cómo se aplica en ai-knowledge

Debes añadir un archivo en la raíz:

ai-knowledge
│
├── VERSION
│
├── skills
├── architecture
├── dev_practices
├── ai_collaboration
├── prompts
└── standards

Contenido de VERSION:

```
1.0.0
```
