# Where each SDD capability lives, and why

```text
ai-native
├── foundation + platform code   behaviour that runs and can be tested
├── knowledge                    methodology that is read on demand
└── template / consumer          the minimum needed to connect a project
```

Rule: reusable and evolving goes to the platform release (foundation/knowledge/runtime/core/contracts); strictly local goes to the consumer.

| Capability | Lives in | Why there |
|---|---|---|
| Conceptual model: roles, work units, levels, modes, command catalog | `contracts/sdd-workflow.json` (+ schema) | data, versioned, validated; the only source |
| Level budgets, state machine, ASSESS, convergence | `contracts/sdd-levels.json`, `runtime/circuit/` | already executable and tested; reused, not copied |
| Classification, tasks parsing, status, spec-folder validation | `runtime/circuit/sdd-workflow.mjs` | pure functions, unit tested |
| `implement-all` loop, Coordinator pipeline, handoff validation | `runtime/circuit/implement-all.mjs`, `coordinator.mjs` | agent-neutral loops with injected agents |
| Command bodies | `core/commands/*.md` | prompts owned by the platform, like `core/roles/*.md` |
| Per-tool commands (`.claude/commands`, `.opencode/commands`) | generated by `runtime/adapters/commands.mjs` | projections; never edited, drift is detected |
| Methodology (levels, EARS, clarify, plan, tasks, TDD, review, change) | `knowledge/sdd/methodology/` | reusable, loaded one file per phase |
| Router | `.agents/skills/sdd/SKILL.md` | tiny; tells the agent what to load |
| Always-on rules | `AGENTS.md` | router + non-negotiables; detail in `knowledge/sdd/agents-contract-detail.md` (shipped; a consumer reads it with `ai-native run -- knowledge sdd/agents-contract-detail.md`) |
| Feature-artifact templates | `knowledge/sdd/feature-templates/` | one copy for every project; a project overrides by file in `.specify/templates/` |
| State of work | Git, governance, validators, evidence | authoritative; memory is auxiliary only |
| Pin to a platform version, local customization | `ai-native.lock.json`, consumer-local files | the only things that must be physically local |

## What is distributed, and what a consumer holds

The release bundle (`runtime/release/bundle.mjs`) ships `runtime/ contracts/ core/ mcp/ profiles/ audit/ .agents/skills/` and the subset `knowledge/sdd/` (not `goals/`; not the rest of `knowledge/`). It is installed in the content-addressed cache and verified by hash before use, so the knowledge is available offline.

```text
consumer repo (physical)                      central (release, via lock + cache)
├── ai-native.lock.json   pin + digest        ├── runtime / contracts / core   foundation
├── AGENTS.md  CLAUDE.md  router + bridge     ├── knowledge/sdd                methodology, templates, detail
├── generated projections (.claude .opencode  └── .agents/skills               skill sources
│   .codex), journaled by hash, never edited
└── project state: specs, STATUS, constitution, optional .specify/templates overrides
```

Resolution is deterministic: lock -> digest -> verified cache entry -> `knowledge/<package>/KNOWLEDGE.json` compatibility -> file. Outcomes are explicit: `OK`, `NOT_ADOPTED`, `MISSING_REFERENCE` (not synced, or not in that release; run `ai-native sync`), `INCOMPATIBLE_VERSION` (unsupported schema, wrong workflow contract, or platform older than `minPlatform`). `consumer.mjs --drift` reports `CLEAN | OUTDATED | DRIFT | MISSING_REFERENCE | INCOMPATIBLE_VERSION`.

## Authority

```text
AGENTS.md -> constitution (core/constitution.md, .specify/memory/constitution.md) -> contracts + skills -> active work unit
```

## How a consumer receives improvements

Referenced and pinned (platform), generated deterministically (adapters, skills, commands), copied only for new generated projects (the `template/` payload). An improvement to foundation or knowledge reaches consumers by bumping the pinned release; local files change only through the delta-only upgrade (`runtime/adapters/consumer.mjs --upgrade --plan`, then without `--plan`), which never overwrites an edited file.

## Portability

The source is agent-neutral. `.claude/`, `.opencode/`, `.codex/` are projections. Codex has no per-project command surface, so it reaches the same procedures through `AGENTS.md` routing and the `sdd` skill. Headroom and future agents consume the same `AGENTS.md` and skill.

## Naming

Implementer is the role (runtime id `builder`, kept for the 3.x line); implement is the action (`/sdd-implement`, `/sdd-implement-all`).
