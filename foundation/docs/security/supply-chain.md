# Supply Chain Security

## Scope

W1-T6 applies to `ai-foundation` supply chain controls for generated CI artifacts.

## Controls

- Provenance is generated by `.github/workflows/supply-chain.yml` with `actions/attest@v4`.
- The verifiable subject is `ai-foundation-source-${{ github.sha }}.tar.gz`.
- Artifact integrity is checked with a SHA-256 checksum before upload and again before attestation.
- The packaged artifact explicitly excludes local, generated, and sensitive paths:
  `.git`, `.env`, `.env.*`, `node_modules`, `.next`, `logs`, `coverage`, `dist`, `build`, `tmp`, `*.log`, and `*.tsbuildinfo`.
- The workflow runs typecheck and build validation before creating the artifact.

## Artifact Verification

After a workflow run, download the `ai-foundation-supply-chain-<sha>` artifact and verify:

```bash
sha256sum --check ai-foundation-source-<sha>.tar.gz.sha256
```

## Provenance Verification

Remote attestation verification requires a completed GitHub Actions run and the GitHub CLI:

```bash
gh attestation verify ai-foundation-source-<sha>.tar.gz -R <owner>/<repo>
```

For offline verification, download the attestation bundle and trusted roots first:

```bash
gh attestation download ai-foundation-source-<sha>.tar.gz -R <owner>/<repo>
gh attestation trusted-root > trusted_root.jsonl
gh attestation verify ai-foundation-source-<sha>.tar.gz -R <owner>/<repo> --bundle <bundle.jsonl> --custom-trusted-root trusted_root.jsonl
```

## SLSA Readiness

This repository is ready to produce GitHub artifact attestations for CI-generated source artifacts. Remote GitHub validation remains required before governance closure because local execution cannot produce or verify hosted GitHub attestations.
