## SemVer

No rompe locks, no cambia el kernel de `AGENTS.md`, el contrato de bootstrap ni ningún schema, y no retira ni cambia de forma incompatible una skill del core (no MAJOR). No agrega skills, perfiles, servidores MCP, gates ni campos de schema (no MINOR según la política). Amplía con texto compatible una skill existente, ajusta triggers de CI y declara la versión del CLI: **PATCH**. Límite honesto: en SemVer genérico una guía nueva podría leerse como funcionalidad compatible (MINOR); la política del repositorio, que es la autoridad, no la clasifica así.

## Límites honestos

* Capability Routing es una guía de prompt, no un control determinista: no hay evaluación con agentes reales de los casos A–E. Lo cubren el texto de la política y un test E2E que exige que llegue a la skill y a los tres roles proyectados del consumidor y que no nombre proveedores.
* Los consumidores Codex no reciben la skill `sdd` (no hay destino de skills para Codex); es el mismo límite que ya tiene todo el routing SDD.
* `develop` no tiene ruleset: sus checks son informativos. El fallo de Docker exit 125 del `pilot` offline en `ubuntu-latest` queda fuera de alcance y puede repetirse en la PR `develop` → `main`.
