## Defecto y causa raíz

`buildClaudeAgentFile` (`runtime/adapters/claude.mjs`) escribía `description: ${role.description}` como escalar YAML plano. Desde `323dd4c` (v3.4.0) la descripción del `reviewer` en `core/agents.json` contiene `lectura: verifica`, y `: ` dentro de un escalar plano es un indicador de mapeo: el frontmatter de `.claude/agents/reviewer.md` deja de ser YAML válido (PyYAML 6.0.3: `mapping values are not allowed here`, línea 2, columna 51). `planner` y `builder` seguían siendo válidos por azar. El mismo código truncaba en silencio una descripción con ` #` (comentario YAML).

## Corrección

`description` se escribe como cadena JSON, que es un escalar YAML entre comillas dobles válido (el criterio que ya usa `runtime/adapters/commands.mjs`): una sola línea, valor exacto. JSON deja sin escapar DEL, los controles C1, U+2028/U+2029 y U+FFFE/U+FFFF, que YAML 1.1 rechaza o pliega; se escapan como `\uXXXX` (U+FFFE/U+FFFF los señaló la revisión independiente sobre `4ad607a`). Con eso, todo lo que emite `JSON.stringify` (escapes JSON, surrogates sueltos como `\udXXX`, pares no-BMP) es imprimible para YAML 1.1. No se usa `yamlString` de `commands.mjs` porque colapsa los espacios y no conservaría la descripción exacta. `name`, `tools`, `model`, `effort` y el cuerpo Markdown no cambian; `core/agents.json` no cambia.

## Regresión (RED/GREEN)

`runtime/adapters/claude.test.mjs`, con el generador real: `: `, `#`, comillas, barra invertida, saltos de línea y tabulador, indicadores YAML iniciales, caracteres que YAML 1.1 pliega, y planner/builder/reviewer proyectados desde `core/agents.json` (cinco campos en orden, descripción exacta, cuerpo). Node no trae parser YAML y no se agregan dependencias: el test fija la forma serializada (un escalar entre comillas dobles por línea), exige que solo contenga caracteres imprimibles de una línea según YAML 1.1 (lista tomada de la especificación, no del generador) y recupera el valor exacto. El documento completo se verificó además con PyYAML.

Conclusiones, sin ir más allá de la evidencia:

* El defecto YAML está demostrado y corregido.
* Claude Code 2.1.311 tolera ese YAML inválido: según la transcripción de sesión que guarda Claude Code (`~/.claude/projects/…`; el stream-json de `-p` solo lista nombres de agentes), muestra al modelo la descripción completa del `reviewer` en ambas versiones. El error «Agent type 'reviewer' not found» **no se reprodujo**: su causa no queda demostrada y este parche **no** declara resuelto ese incidente.
* La revisión independiente atestada termina `NOT_PROVEN` en ambas versiones por una causa distinta y ajena al YAML: Claude Code 2.1.311 inyecta un recordatorio de `SubagentHandback` como segundo turno del Reviewer y el Reviewer entrega su informe con esa herramienta; la plataforma lo cuenta como un mensaje posterior a la delegación y no encuentra un veredicto final legible, y falla cerrada. Queda fuera del alcance de este parche (no se modifica Independent SDD Review); requiere una tarea propia.

## Límites honestos

* El incidente «reviewer not found» no se reprodujo con 2.1.311; versiones anteriores de Claude Code (2.1.305/2.1.306 en los E2E de v3.4.0) también ejecutaron el `reviewer` con el YAML inválido. No hay evidencia de qué versión, si alguna, rechaza ese archivo.
* Con Claude Code 2.1.311 ninguna revisión independiente queda atestada (`NOT_PROVEN`) por el defecto de `SubagentHandback` descrito arriba, tanto en `v3.4.0` como en esta candidata. Fail-closed preservado; sin scope abierto.
* En el host Windows, corridas sueltas en paralelo de los tests de adapters y de cli/release mostraron el flake conocido `Permission denied` al escribir `.git/objects` en repos temporales (N-29); en serie pasan. Los `Permission denied` del paso de migrate-inventory son avisos de git al recorrer carpetas del perfil de usuario, no fallos.
* Por falta de memoria en el host, la batería local se corrió en grupos secuenciales, y el paso «Release gates» de `release.yml` descompuesto (sus validadores más los tests que ningún paso de `ci.yml` cubre); en una sola invocación solo corre en la CI remota.
