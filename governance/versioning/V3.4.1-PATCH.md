# v3.4.1 — parche de plataforma (YAML del agente `reviewer` de Claude Code)

Estado: **CANDIDATA sin tag ni release** en la rama `release/v3.4.1` (encargo explícito del humano, 2026-10-27), creada desde `develop` en `036e6f8` (merge de #153, que reconcilió `main` → `develop`: `15f35ff` es ancestro, árbol idéntico). `v3.4.0` (`15f35ff`) es inmutable y no se toca. La promoción es humana: PR `release/v3.4.1` → `develop`, PR `develop` → `main` con merge commit, `release-gate` sobre el informe del SHA auditado, tag y `release.yml`. **Publicar está sujeto a una decisión humana previa** (ver «E2E real»): el incidente operativo original no se reprodujo. SemVer: **PATCH**, justificado abajo.

## Defecto y causa raíz

`buildClaudeAgentFile` (`runtime/adapters/claude.mjs`) escribía `description: ${role.description}` como escalar YAML plano. Desde `323dd4c` (v3.4.0) la descripción del `reviewer` en `core/agents.json` contiene `lectura: verifica`, y `: ` dentro de un escalar plano es un indicador de mapeo: el frontmatter de `.claude/agents/reviewer.md` deja de ser YAML válido (PyYAML 6.0.3: `mapping values are not allowed here`, línea 2, columna 51). `planner` y `builder` seguían siendo válidos por azar. El mismo código truncaba en silencio una descripción con ` #` (comentario YAML).

## Corrección

`description` se escribe como cadena JSON, que es un escalar YAML entre comillas dobles válido (el criterio que ya usa `runtime/adapters/commands.mjs`): una sola línea, valor exacto. JSON deja sin escapar DEL, los controles C1 y U+2028/U+2029, que YAML 1.1 rechaza o pliega; se escapan como `\uXXXX`. No se usa `yamlString` de `commands.mjs` porque colapsa los espacios y no conservaría la descripción exacta. `name`, `tools`, `model`, `effort` y el cuerpo Markdown no cambian; `core/agents.json` no cambia.

## Regresión (RED/GREEN)

`runtime/adapters/claude.test.mjs`, con el generador real: `: `, `#`, comillas, barra invertida, saltos de línea y tabulador, indicadores YAML iniciales, caracteres que YAML 1.1 pliega, y planner/builder/reviewer proyectados desde `core/agents.json` (cinco campos en orden, descripción exacta, cuerpo). Node no trae parser YAML y no se agregan dependencias: el test fija la forma serializada (un escalar entre comillas dobles por línea) y recupera el valor exacto. El documento completo se verificó además con PyYAML.

Conclusiones, sin ir más allá de la evidencia:

* El defecto YAML está demostrado y corregido.
* Claude Code 2.1.311 tolera ese YAML inválido (muestra al modelo la descripción completa del `reviewer`). El error «Agent type 'reviewer' not found» **no se reprodujo**: su causa no queda demostrada y este parche **no** declara resuelto ese incidente.
* La revisión independiente atestada termina `NOT_PROVEN` en ambas versiones por una causa distinta y ajena al YAML: Claude Code 2.1.311 inyecta un recordatorio de `SubagentHandback` como segundo turno del Reviewer y el Reviewer entrega su informe con esa herramienta; la plataforma lo cuenta como un mensaje posterior a la delegación y no encuentra un veredicto final legible, y falla cerrada. Queda fuera del alcance de este parche (no se modifica Independent SDD Review); requiere una tarea propia.
