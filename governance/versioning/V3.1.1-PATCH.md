# v3.1.1 — parche de plataforma

Estado: **CANDIDATA** (PR #102). `v3.1.0` es inmutable y no se modifica ni se mueve. Este parche corrige defectos hallados en la validación post-release de `v3.1.0` (`V3.1.0-POST-RELEASE-VERIFICATION.md`) y nada más.

## Defectos corregidos

| ID | Severidad | Causa | Corrección | Regresión |
|---|---|---|---|---|
| F-17 | HIGH (funcional) | Los comandos proyectados mandaban ejecutar `node runtime/policy/hitl.mjs`, `contracts/sdd-levels.json`, `runtime/circuit/implement-all.mjs`, que no existen en un consumidor; además `ai-native` no es un ejecutable y nada decía cómo invocar la release | Lanzador proyectado `.ai-native/ai-native.mjs` (generado, con drift): lee el digest del lock, localiza la release en la caché y ejecuta su bootstrap (que verifica el digest). Nuevos subcomandos públicos de `ai-native run`: `hitl`, `sdd validate\|status\|next\|mark\|budget`. Comandos y skill `sdd` reescritos para usar solo el lanzador | `runtime/adapters/consumer-launcher.test.mjs`: ejecuta contra una caché sincronizada **cada línea de comando** que los comandos proyectados dan a un agente; falla si un comando nombra una ruta privada o un `node` fuera del lanzador |
| F-18 | MEDIUM | `forbiddenImports` normalizaba el import observado (`node:` fuera) pero no la regla: `"node:fs"` nunca coincidía | Normalización simétrica en ambos lados (JS: `node:`; Python: `.` ↔ `/`) | `architecture.test.mjs`: `fs`/`node:fs`/`node:fs/promises`, sin falsos positivos (`fs-extra`, `node:path`, regla más específica) y Python con puntos |
| F-19 | MINOR→necesario | `human_gate: none` solo se podía demostrar con un perfil de laboratorio: ningún camino publicado lo habilitaba | Opt-in publicado `lock.governance.allowNone` (esquema `lock.schema.json`), leído **del lock de la rama base** (un PR no se lo concede). `hitl` y el gate L3 usan la misma función. Defecto seguro: ausente = apagado. Alto riesgo, control plane, release y production siguen forzando `required` | `consumer-launcher.test.mjs` (4 casos: apagado, encendido con bajo riesgo, alto riesgo/control plane/release/production, PR que se auto-concede) |

## F-16 (`AGENTS.md`)

No se amplía el parche. `AGENTS.md` es **local por contrato** (`KEEP_LOCAL`: router y hechos del proyecto; lo aporta el scaffold `template/templates/project`). La release proyecta `CLAUDE.md`/`opencode.json` que lo referencian. Lo único cambiado: el `AGENTS.md` del scaffold dice ahora cómo se invoca la release (`node .ai-native/ai-native.mjs <command>`). Aviso si falta `AGENTS.md` queda en el backlog (no rompe un consumidor válido).

## Compatibilidad

Aditivo: un fichero proyectado nuevo (`.ai-native/ai-native.mjs`), subcomandos nuevos y un campo opcional del lock. Los consumidores `v3.1.0` reciben el delta con `--upgrade` (comandos actualizados + lanzador). `contracts/lock.schema.json` y `AGENTS.md` del scaffold son control plane / contrato: la PR requiere revisión humana.

## Validación E2E de desarrollo (agente real, bundle construido del árbol candidato)

Cada escenario usa un consumidor temporal propio (lock + `sync` + proyecciones, sin rutas a la fábrica), un escenario por vez. Modelos: Claude Haiku 4.5 (spec/plan/tasks) y Sonnet 5.5 (implementación y revisión). Coste: ≈ 1,9 USD los runs finales que pasan; ≈ 3,5 USD contando los intentos que fallaron y motivaron las correcciones de abajo.

### Defectos encontrados por la propia E2E y corregidos antes de congelar

| Hallazgo | Causa | Corrección |
|---|---|---|
| El agente validaba pero no podía corregir `tasks.md` | `tasks.md has no tasks` / `invalid task line` no decían el formato esperado | los errores incluyen el formato (`expected "- [ ] **T1. Title.** RF-1" … "Done when"`); regresión en `sdd-workflow.test.mjs` |
| `/feature` podía entregar sin validar | la validación era un párrafo, no el último paso | paso final obligatorio y «nunca informar sin PASS»; una Feature nunca es `light` |
| `plan.md` de 167 líneas y 8 tasks para una función | sin guía de tamaño; tasks que solo escriben tests | plan proporcional al cambio; cada task lleva su test y su código (TDD dentro de la task) |
| `/sdd-implement-all`: sin RED, todas las tasks marcadas de golpe, sin revisor | texto blando | pasos explícitos RED→GREEN→marcar una task→siguiente; revisor `reviewer` obligatorio con `VERDICT`; si no hay subagentes se declara |
| `hitl --base HEAD` daba `final-only` sin ver la declaración `none` | `<base-ref>` sin definir y el CLI solo miraba commits | el comando define `<base-ref>` (la rama destino, nunca `HEAD`); `hitl` evalúa commits + árbol de trabajo + ficheros nuevos (solo puede endurecer); regresión en `consumer-launcher.test.mjs` |
| El coordinador terminaba su turno esperando a un subagente asíncrono (la ejecución se cortaba) | falta de instrucción | subagentes en primer plano, nunca terminar el turno con uno activo |
| Mensaje de `none` rechazado apuntaba al perfil | texto desactualizado | indica `governance.allowNone` en el lock de la rama base |
