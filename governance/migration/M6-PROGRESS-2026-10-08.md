## Brechas de plataforma halladas (no corregidas en `v3.0.1`)

1. **El migrador retira `requirements-dev.txt` idéntico a Template, pero el `productSetupCommand` de `python-lib`/`python-service` lo exige** (`pip install . -r requirements-dev.txt`). En `gi-common-crm` el gate L3 habría fallado por archivo inexistente; el consumidor lo repuso como archivo propio del producto.
2. **Los perfiles Python asumen un paquete instalable en la raíz** (`pip install .`). `gi-ocr`, `gi-ot` y `gi-clinicadental` son aplicaciones (pip + requirements, sin `[build-system]`): se les declaró un paquete vacío solo para que el setup sea válido. Falta un perfil de aplicación Python no instalable.
3. **El gate de integridad exige marcadores `STATUS:AUTO`** en `STATUS.md` cuando existe; `gi-clinicadental` no los tenía. No hay herramienta de plataforma que escriba el bloque.
4. **La poda del circuito Template no es completa por el migrador**: los scripts/tests/workflows modificados o locales que dependen de archivos retirados (`.agentic/*`, `workunit-lib`) siguen en el repo y fallan; cada consumidor debió retirar sus tests/pasos huérfanos (documentado commit a commit en cada PR).

Cada punto es candidato a una versión posterior de la plataforma; ninguno se corrigió aquí (requieren PR a `ai-native` con merge humano).
