## What it proves, and what it does not

- RF-14: the Regions -> Locales dependency is the schema FK `region_locale_locale_fk` -> `reference.locale`, read
  from `pg_constraint`; no HTTP client is involved.
- RF-15: Locales and Regions are written to and read back from a real disposable PostgreSQL through GI's public
  incorporation functions and read API; names resolve by `locale_id`.
- RF-16: a nonexistent locale reference is rejected by referential integrity with the state unchanged; a rejected
  snapshot writes nothing; two fresh databases reach the same normalized rows and row counts; a resubmitted
  snapshot is a no-op; the whole case set was run twice in independent pytest sessions (fresh container each).
- RF-17: classes are labelled by name and in the plan (`executionKind`); API checks are FastAPI TestClient
  in-process, never HTTP-socket end to end; `test_sim_*` use no database.
- Not proven here: HTTP over a real socket (deliberately not claimed); runner isolation (`restricted`); behavior
  of other GI catalogs (Countries, Currencies, Units) under Native Acceptance.

The first two CI attempts (`974599d`, `1ed1700`) were BLOCKED, not FAIL: pytest ran the 12 cases against
PostgreSQL but could not open `/dev/stdout` (a socket under Node) for its JUnit report, so the platform saw no
structured output and failed closed. Fixed in `4ecf0fd` (declared runner result file), not by relaxing a check.
