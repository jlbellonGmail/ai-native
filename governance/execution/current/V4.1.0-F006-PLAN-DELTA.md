## 2. Defect (verified, read-only)

* `canonical()` (`runtime/bootstrap/install.mjs:45`) serializes only `schemaVersion`, `platform`, `profiles`,
  `mcpProfiles`, `packs` and `overrides`.
* `contracts/lock.schema.json` (`additionalProperties: false`) also admits `productDir` and `governance`. The
  `platform` subkeys match the schema (`repo`, `version`, `commit`, `digest`, `channel`).
* `rollback()` (`install.mjs:262-263`) writes `{ ...lock, platform: {...} }` through `canonical()`, so
  **`productDir` and `governance` are lost**, and rollback still reports PASS with no warning.
* `init()` (`:296`) and `migrate.mjs:133` build locks without those fields, so they lose nothing.
* The approved upgrade path is unaffected: `planBump` (`runtime/migrate/bump.mjs:39-42`) serializes the whole lock.
* `sync` records each activated digest in the cache state history (`install.mjs:183`). A consumer that upgrades to
  v4.1.0 and then runs `ai-native rollback` therefore reaches the defect.

Observed (scripts kept outside the repository; temporary directories only):

| Check | Tree | Result |
|---|---|---|
| sync v4.0.2 -> sync v4.1.0 -> rollback, lock with `productDir` + `governance.allowNone` | `3c01335` and `e88de8f` | `rollback: PASS`, `after.productDir: null`, `after.governance: null`, `lost: [productDir, governance]` |
| `planBump` v4.0.2 -> v4.1.0 on the same lock | `3c01335` | both fields kept |
| rollback of a lock with a field outside the schema / `productDir: "../escape"` | `3c01335` | `FAIL` with the schema error; lock bytes unchanged; no cache state written |

Impact on a consumer:

* `productDir` reverts to the repository root, so L3 runs `productSetupCommand`/`productTestCommand` in another
  directory. It may fail, or pass without testing the product.
* `governance.allowNone` reverts to off. That is the fail-safe direction, but it is still an unrequested policy
  change.
