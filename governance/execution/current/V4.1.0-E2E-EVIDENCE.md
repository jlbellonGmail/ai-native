# v4.1.0 — End-to-end proof on a disposable consumer (spec 003 RF-21, T6)

Date: 2026-11-25. Platform: candidate worktree `feature/native-acceptance-v4.1.0` (working tree after commit of this record; the consumer launcher `.ai-native/ai-native.mjs` was a shim to the candidate `runtime/main.mjs`). Consumer: a disposable git repo `text-tools` in the session scratchpad (deleted after the run). No gi-* repository was used.

## Part A — normal feature run by a Builder agent (no acceptance-specific instruction)

A Builder subagent (Claude Sonnet, same machine, NOT an isolated or attested reviewer) received only the product request (`wordCount(text)`, reject non-strings) and the projected bodies of `/sdd-spec`, `/sdd-plan`, `/sdd-tasks`, `/sdd-implement-all`. It reported (its own words, summarized):

- `/sdd-spec` produced `AC-1..AC-4` citing RF-1..RF-5; `/sdd-tasks` produced T1..T3 with T3 = the acceptance task (activation came from the command bodies, not from the prompt).
- RED/GREEN per task; `sdd acceptance plan` -> `PLAN: VALID (4 criteria)`; `sdd acceptance manual` -> `PARITY: PASS`.
- `sdd acceptance run` -> cases C-1..C-5 PASS, `ACCEPTANCE: BLOCKED` with `PENDING_APPROVAL: NOT_APPLICABLE_PENDING_APPROVAL` (it declared integration, contract, persistence, cross-cutting NOT_APPLICABLE with justifications).
- `hitl --base main` after the work: `risk high, human_gate required` (CONTRACT_CREATED + NOT_APPLICABLE_DECLARED). `sdd review status`: `FINAL_REVIEW_STATUS: REVIEW_PENDING`, `HUMAN_GATE: required`. It stopped there and simulated no approval.
- Usability defects it reported, fixed in this candidate: `sdd acceptance manual` crashed with ENOENT without a contract; no contract proposal was generated; `VALIDATION: FAIL` showed no reason.

Datasets: the Builder used inline synthetic values only (`datasets: []`), which the plan schema allows; digest/seed dataset rules are proven by `runtime/acceptance/plan.test.mjs`.
